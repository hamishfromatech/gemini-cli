# A-Coder CLI authentication setup

To use A-Coder CLI, you'll need an OpenAI-compatible API key. This guide helps you
quickly find the best way to authenticate based on your setup.

> [!TIP]
> Looking for a high-level comparison of all available subscriptions?
> To compare features and find the right quota for your needs, see our
> [Plans page](https://a-coder-cli.com/plans/).

For most users, we recommend setting your API key as an environment variable and
starting A-Coder CLI.

## Choose your authentication method <a id="auth-methods"></a>

Select the authentication method that matches your situation in the table below:

| User Type / Scenario                                                   | Recommended Authentication Method                                | Cloud Project Required                               |
| :--------------------------------------------------------------------- | :--------------------------------------------------------------- | :---------------------------------------------------------- |
| Individual users with an OpenAI API key                              | [Use OpenAI API Key](#api-key)                                   | No                                                          |
| Organization users with a custom base URL                              | [Use a custom provider](#custom-provider)                        | No                                                          |
| [Headless mode](#headless)                                             | [Use OpenAI API Key](#api-key)                                    | No                                                          |

### What API providers are supported?

- **OpenAI-compatible providers:** A-Coder CLI works with any provider that implements
  the OpenAI Chat Completions API, including OpenAI, Azure OpenAI, and self-hosted endpoints.

- **Custom base URLs:** Use `A_CODER_BASE_URL` or `OPENAI_BASE_URL` to point A-Coder CLI
  at a compatible proxy or on-premise deployment.

## (Recommended) Use an OpenAI-compatible API key <a id="api-key"></a>

If you run A-Coder CLI on your local machine, the simplest authentication method
is setting your OpenAI-compatible API key as an environment variable.

If you are using a provider other than OpenAI, you may also set `A_CODER_BASE_URL`.

To authenticate and use A-Coder CLI:

1. Set your API key:

   ```bash
   export A_CODER_API_KEY="YOUR_API_KEY"
   # Optional: point to a custom OpenAI-compatible endpoint
   export A_CODER_BASE_URL="https://api.openai.com/v1"
   ```

2. Start the CLI:

   ```bash
   a-coder-cli
   ```

   Your credentials will be read from the environment for each session.

### Do I need a cloud project?

No. A-Coder CLI does not require a cloud project. Authentication is handled entirely
through your OpenAI-compatible API key and optional base URL.

## Use a custom provider <a id="custom-provider"></a>

A-Coder CLI can be configured to use any OpenAI-compatible API endpoint.

To authenticate with a custom provider:

1. Obtain your API key and endpoint URL from your provider.

2. Set the `A_CODER_API_KEY` environment variable and, if needed, `A_CODER_BASE_URL`.

   <Tabs>
     <TabItem label="macOS/Linux">

     ```bash
      # Replace with your actual API key
      export A_CODER_API_KEY="YOUR_A_CODER_API_KEY"
     ```

     </TabItem>
     <TabItem label="Windows (PowerShell)">

     ```powershell
      # Replace with your actual API key
      $env:A_CODER_API_KEY="YOUR_A_CODER_API_KEY"
     ```

     </TabItem>
   </Tabs>

   To make this setting persistent, see
   [Persisting Environment Variables](#persisting-vars).

3. Start the CLI:

   ```bash
   a-coder-cli
   ```

> [!WARNING]
> Treat API keys, especially for services like OpenAI, as sensitive
> credentials. Protect them to prevent unauthorized access and potential misuse
> of the service under your account.

## Running in headless mode <a id="headless"></a>

[Headless mode](../cli/headless.md) will use your existing authentication
method, if an existing authentication credential is cached.

If you have not already signed in with an authentication credential, you must
configure authentication using environment variables:

- [Use OpenAI-compatible API Key](#api-key)
- [Use a custom provider](#custom-provider)
